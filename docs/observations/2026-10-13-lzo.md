## Independent reference and coverage

Official miniLZO 2.10 was downloaded from Oberhumer's site, checked against its
published archive SHA-1, then built locally from unchanged source. Its safe
decoder independently decoded every unequal-size game block. The compiler,
source and DLL hashes are recorded in the local reference build.json.
See [provenance and reproduction](../../references/lzo.md).

Hand vectors cover empty data, literals, short matches, state transitions,
overlapping copies, extended lengths and 2 KiB/16 KiB/48 KiB distance families.
Reference-generated cases use deterministic random, zero-filled and periodic
data at 11 lengths from zero through 131,072. Rejection tests cover every
truncation of a selected valid stream, invalid references, wrong output sizes,
noncanonical endings and extra compressed bytes. Framing tests cover verbatim
blocks, multiple blocks, output caps, retained tails, manifests and refusal to
overwrite or write under game. Reparse-point rejection is not tested here.

The optional full run creates `reports/lzo-*/verification.json` and
`decoded-resources.csv`, containing IDs, stored/decoded/tail hashes and sizes.
No original game source was used. No upstream decoder was copied into the
OpenJade runtime. Reference comparison supports codec correctness on these
inputs; it does not prove correctness on every possible stream or explain the
decoded resource structures. Rendering and game execution are still unimplemented.
